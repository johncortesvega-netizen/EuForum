# About European Public Square

European Public Square is a free, slower multilingual forum prototype for Europe.

It is built to test a public-square model: structured rooms and threads, original-language preservation, visible receipts, accountable identity, human review, appeal paths, and donation transparency without donor influence.

This is a private alpha candidate. It is not a public launch.

## Feature Implementation Map

| Feature | What it does | How it is implemented in this prototype |
| --- | --- | --- |
| Old-school forum structure | Uses rooms, threads, and replies instead of an algorithmic feed. | Frontend data is loaded from `data/localData.js`; the UI renders categories, rooms, thread lists, post cards, and recent threads in `app.js`. |
| Local posting | Lets testers create local demo threads and replies. | Composer state lives in browser page memory. Local drafts disappear on refresh unless the optional backend is running and logged-in posting is used. |
| Posting limits | Slows down spam, rage loops, and compulsive posting. | `app.js` tracks post attempts in page memory with a 3-posts-per-30-minutes demo window and a 45-second cooldown. |
| Accountable identity display | Shows name + country on posts; photo is optional. | Local composer fields collect display name and country; backend login can supply display name + country when FastAPI is running. Receipts record the identity-display boundary. |
| Minimal backend login | Supports accountable posting without a hidden profile. | `backend/eps_backend.py` exposes `/api/auth/register`, `/api/auth/login`, `/api/auth/me`, and `/api/auth/logout`; passwords use PBKDF2; sessions use bearer tokens. Frontend tokens stay in page memory only. |
| Frontend/backend connection | Allows logged-in posting and moderation dashboard calls when backend is running. | `app.js` has a small API client targeting `http://127.0.0.1:8000`; it posts new threads/replies and reads review queue endpoints when available. |
| Original-language and translation layer | Keeps the original visible and treats translation as a bridge. | Posts render original text beside reader-language text. Translation receipts are generated by `data/receiptSystem.js`; real translation provider is not connected. |
| Sydney Protocol clarify-only prompts | Surfaces context questions without judging or enforcing. | `data/protocolRules.js` performs local keyword/pattern analysis. `app.js` renders prompt previews and receipts. Prompts do not hide, rank, punish, or decide truth. |
| Visible receipts | Makes platform actions inspectable. | `data/receiptSystem.js` creates post, identity, translation, protocol, report, moderation, evidence, spending, and appeal receipts. `app.js` renders receipt cards and a filterable ledger. |
| Human review pipeline | Routes reports to accountable human moderation. | Local review state lives on posts in `app.js`; backend endpoints exist for reports, review queue, and review actions. Serious actions include temporary hide and two-moderator panel review. |
| EU hard-boundary map | Separates direct-harm categories from Sydney Protocol clarification. | `data/euHardBoundaryMap.js` and backend `/api/policy/eu-hard-boundaries` list hard-boundary categories and THRESHOLD examples. It is policy mapping, not automatic filtering. |
| Evidence reviewer notes | Adds source/context notes without truth verdicts. | `data/evidenceReview.js` defines note types and demo reviewers. `app.js` attaches evidence notes and evidence receipts to posts. Backend placeholder endpoints exist. |
| Moderation dashboard | Gives moderators a first review queue/action surface. | `app.js` renders a moderation dashboard that loads `/api/review-queue` when backend is available and falls back to local demo queue otherwise. |
| Appeal flow | Lets users challenge serious visibility actions. | Appeal buttons appear when a post review state is appealable. `app.js` tracks submitted/under-review/resolved statuses and creates appeal receipts. |
| Donation transparency | Explains costs without enabling donor influence. | `data/donationTransparency.js` stores mock monthly costs and spending receipts. The UI renders a transparency page; no payment processor is connected. |
| Private alpha readiness pack | Prepares controlled invited testing. | `docs/PRIVATE_ALPHA_*` files provide setup, admin, moderation, evidence review, privacy/rules, limitations, feedback, launch checklist, runbook, invite, onboarding, issue log, shift sheet, session report, and go/no-go docs. |
| Smoke test | Gives a dependency-free readiness check. | `tests/private_alpha_smoke_check.mjs` checks required files, UI markers, receipt functions, docs, status, and forbidden browser persistence APIs. Run with `npm.cmd run smoke` on Windows PowerShell. |

## What Is Not Implemented Yet

- No public launch.
- No public registration.
- No production authentication provider.
- No persistent browser token storage.
- No real translation provider.
- No real donation/payment processing.
- No production moderation case management.
- No production appeal assignment.
- No automated moderation.
- No ranking or algorithmic feed.
- No hidden behavioral profile.

## Core Boundary

European Public Square should make public discussion slower, more accountable, and more reviewable without becoming a surveillance platform, engagement feed, truth machine, or automated censorship system.
